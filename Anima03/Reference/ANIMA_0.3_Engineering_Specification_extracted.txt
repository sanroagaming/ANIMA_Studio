0. About this document
This is the working engineering specification for ANIMA 0.3. It is written to be built from: every feature has a syntax, a typing rule, a runtime behaviour, an error behaviour and a test expectation. Where something is a design choice rather than a fact, it says so.
Status of decisions. Decisions D1 to D6 (section 1) are ratified. Everything marked [Stretch] may be cut without failing 0.3. Everything marked [Reserved] is intentionally not built in 0.3 but its keywords and extension points are protected now.
Evidence base. The 0.2 baseline in section 2 comes from reading the 0.2 Preview sources and from building and running them on Linux with g++ 13 (all three .ani examples pass; the CPU sum returns 500000500000). The Windows/MSVC/D3D12 paths were not exercised. The legacy .anima property and node inventory in section 15 is taken from the shipped samples and docs and must be completed against the full legacy runtime in work package F1 before the migrator is declared done.
Conventions. monospace is source or code. “Must” is a requirement, “should” is a strong default, “may” is optional. Work packages are numbered A1, B3 and so on, by milestone.
1. Executive summary and ratified decisions
1.1 What 0.3 delivers
One language. A single grammar, extension .ani, header ANIMA 0.3. The old .anima dialect is retired and converted by anima migrate.
A real pipeline. Lexer, parser, AST, checker, bytecode compiler, stack VM. Each stage is separately testable. Every syntax and type error is reported, with line, column and a source snippet, before any code runs.
A static type system with local inference: whole (int64), real (float64), text, truth, list of T, map of K to V, maybe T, function types, records, classes, traits, enums, and engine math types.
Functions and closures: parameters, defaults, named arguments, return values, lambdas, lexical scopes.
Objects: records (value semantics), classes (reference semantics, single inheritance, traits, abstract, override, constructors, finishers, weak references), enums.
Modules and capabilities: use / from ... use / export, a project manifest, and a capability list that gates native access (GPU, files, clock).
A standard library of 12 modules (std.core, math, io, json, time, random, log, test, cpu, gpu, host, ui) and roughly 150 functions and methods, plus engine math types.
A C++ host API so engine features arrive as typed native modules that the checker can verify.
Declarative UI as part of the language: app, state, scene, node, on events, with typed node and property catalogues and a scene tree that can be dumped and tested.
A test and tooling baseline: anima run | check | test | repl | migrate | dis | scene, golden-file conformance tests, differential tests against the 0.2 evaluator, fuzzing, benchmarks with thresholds.
1.2 Ratified decisions
1.3 What 0.3 does not do
No ahead-of-time compiler or .exe bundling. No new GPU pipeline (DXR, kernels, resource handles). No native drawing of UI. No user-defined generics. No async, tasks or language-level threads. No raw pointers, manual memory, or dynamic library loading. No package manager. No formatter. These are listed in section 22 with the versions that own them.

3. Lexical specification
3.1 Source files
Encoding: UTF-8. A leading byte-order mark is accepted and ignored. Any invalid UTF-8 sequence is error ANI-L009.
Line endings: LF, CRLF and lone CR are all accepted and normalised to LF for position tracking. Line and column numbers are 1-based; columns count UTF-8 code points, not bytes.
Tab characters are whitespace. The language is not indentation sensitive.
The first non-comment token must be the identifier ANIMA followed by a version number. Version 0.3 is required for this grammar; 0.2 selects the compatibility mode (section 20.4) when the runner is invoked with --compat 0.2, and otherwise reports ANI-P005 with a hint to run anima migrate.
Maximum file size 8 MiB; maximum line length 64 KiB; maximum nesting depth 200 (blocks, parentheses and brackets combined). Exceeding any limit is ANI-L010.
3.2 Comments
# to end of line, // to end of line, and /* block, may span lines, does not nest */. Comments never produce tokens. An unterminated block comment is ANI-L005.
3.3 Identifiers and keywords
Identifiers start with an ASCII letter or underscore and continue with ASCII letters, digits or underscores. Convention: snake_case for values, functions, fields and modules; PascalCase for types, classes, records, enums, traits and UI node types; UPPER_CASE only for constants imported from the host (for example PI). Non-ASCII identifiers are [Reserved] for a later version.
Reserved words (cannot be used as identifiers):
abstract and app as attempt always announce class define each else enum export false fail field fixed fn from give in is let list make map maybe none node not of on or otherwise override perform private project record repeat rescue scene self shared skip start state stop super test to trait true use weak when while with extend finish
(else is reserved but unused, so that it is never confused with otherwise.)
Reserved for future versions (an identifier with these names is error ANI-L011 so that user code will not break later):
async await case generic handle kernel match shader task unsafe where yield native switch
Contextual words (valid identifiers outside their syntax position): click, press, hover, focus (event names after on), fallback (binary operator), step, pick.
3.4 Literals
3.5 Operators and punctuation
+ - * / % == != < <= > >= <- += -= *= /= %= -> .. ..= . , : ; ( ) [ ] { } ?
and, or, not, is, as, with and fallback are word operators. The semicolon is optional and equals a newline, so a <- 1; b <- 2 is legal on one line. ? is [Reserved].
3.6 Newline significance
A newline ends a statement or declaration unless one of the following holds, in which case it is ignored:
The parser is inside ( ) or [ ].
The last token on the line is a binary operator, ,, <-, ->, ., :, (, [, {, or one of the keywords and or not is as with fallback in of to.
The first token on the next line is . (method chaining) or one of the word operators and, or, fallback.
The next token after the newline(s) is otherwise and the previous token was the } closing a when or otherwise when block.
An opening { must be on the same line as the construct that owns it. when x > 1\n{ is error ANI-P012 with the hint “put ‘{’ on the same line”.
3.7 Token structure
Each token carries kind, lexeme (a view into the source), start and end as byte offsets, and line/column of the start. Interpolated text is lexed into a TextStart, a sequence of TextPart and nested expression tokens, and a TextEnd, so the parser never re-scans strings. The lexer produces tokens on demand (pull model) and supports checkpoint and rewind of one token for the parser’s is/as lookahead.
3.8 Lexical errors
ANI-L001 unterminated text literal; L002 invalid escape sequence; L003 invalid number literal; L004 unexpected character; L005 unterminated block comment; L006 reserved for future use; L007 invalid \u{} escape; L008 whole literal out of range; L009 invalid UTF-8; L010 limit exceeded; L011 reserved word used as identifier. The lexer recovers by skipping to the next whitespace or delimiter and continues, so several lexical errors can be reported in one run.
4. Grammar
The grammar is written in EBNF. { x } is zero or more, [ x ] optional, a | b alternatives, NL a significant newline or ;. The parser is hand-written: recursive descent for declarations and statements, Pratt (precedence climbing) for expressions. It must never be generated.
4.1 Program structure
program        := header { top_item } 
header         := "ANIMA" VERSION NL
top_item       := project | use_decl | declaration | start_block | app_decl | test_block
project        := "project" TEXT "{" { project_field } "}"
project_field  := ("target" | "entry" | "version" | "runtime") qname NL
                | "paths" TEXT { "," TEXT } NL
                | "capability" qname NL
use_decl       := "use" qname [ "as" IDENT ] NL
                | "from" qname "use" IDENT { "," IDENT } NL
declaration    := [ "export" ] ( function | record | class | trait | enum | const_decl | extend )
const_decl     := "fixed" IDENT [ ":" type ] "<-" expr NL
start_block    := "start" block
test_block     := "test" TEXT block
4.2 Functions, types and members
function       := "define" IDENT "(" [ params ] ")" [ "->" type ] block
params         := param { "," param }
param          := IDENT ":" type [ "<-" expr ]
lambda         := "fn" "(" [ params ] ")" [ "->" type ] block
record         := "record" IDENT "{" { rec_member } "}"
rec_member     := IDENT ":" type [ "<-" expr ] ( NL | "," ) | function
class          := [ "abstract" ] "class" IDENT [ "is" qname { "," qname } ] "{" { class_member } "}"
class_member   := [ "private" ] [ "shared" ] "field" IDENT ":" type [ "<-" expr ] NL
                | [ "private" ] [ "shared" ] [ "override" | "abstract" ] function
                | "make" "(" [ params ] ")" block
                | "finish" block
trait          := "trait" IDENT [ "is" qname { "," qname } ] "{" { trait_member } "}"
trait_member   := "define" IDENT "(" [ params ] ")" [ "->" type ] [ block ]
enum           := "enum" IDENT [ ":" "whole" ] "{" enum_case { ( "," | NL ) enum_case } "}"
enum_case      := IDENT [ "<-" INTEGER ]
extend         := "extend" qname "{" { function } "}"                 [Stretch]
type           := qname | "list" "of" type | "map" "of" type "to" type | "maybe" type
                | "weak" qname | "fn" "(" [ type { "," type } ] ")" [ "->" type ]
qname          := IDENT { "." IDENT }
4.3 Statements
block          := "{" { statement } "}"
statement      := let_stmt | assign_stmt | expr_stmt | when_stmt | repeat_stmt
                | give_stmt | stop_stmt | skip_stmt | announce_stmt | fail_stmt
                | attempt_stmt | perform_stmt | const_decl | block
let_stmt       := "let" IDENT [ ":" type ] "<-" expr NL
assign_stmt    := target ( "<-" | "+=" | "-=" | "*=" | "/=" | "%=" ) expr NL
target         := IDENT | expr "." IDENT | expr "[" expr "]"
when_stmt      := "when" expr block { "otherwise" "when" expr block } [ "otherwise" block ]
repeat_stmt    := "repeat" ( expr | "while" expr | "each" IDENT [ "," IDENT ] "in" expr
                           | IDENT "in" range_expr ) block
give_stmt      := "give" [ expr ] NL
stop_stmt      := "stop" NL
skip_stmt      := "skip" NL
announce_stmt  := "announce" expr NL
fail_stmt      := "fail" expr NL
attempt_stmt   := "attempt" block { "rescue" IDENT [ ":" qname ] block } [ "always" block ]
perform_stmt   := "perform" IDENT NL                                   (deprecated)
expr_stmt      := expr NL                                              (must be a call)
repeat each k, v in some_map iterates key and value. repeat each i, item in some_list is not supported; use repeat i in 0..list.length().
4.4 Expressions and precedence
Comparison and equality operators do not chain: a < b < c is ANI-P013. Assignments are statements, never expressions.
primary        := INTEGER | REAL | TEXT | "true" | "false" | "none" | IDENT | "self" | "super" "." IDENT
                | "(" expr ")" | list_lit | map_lit | lambda
call_args      := "(" [ arg { "," arg } ] ")"
arg            := [ IDENT ":" ] expr
record_with    := expr "with" "{" IDENT ":" expr { "," IDENT ":" expr } "}"
4.5 UI declarations
app_decl       := "app" IDENT "{" { state_decl | scene_decl | function } "}"
state_decl     := "state" IDENT [ ":" type ] "<-" expr NL
scene_decl     := "scene" IDENT "{" { node_decl } "}"
node_decl      := "node" IDENT [ ":" qname ] "{" { node_member } "}"
node_member    := IDENT ":" expr ( NL | ";" )
                | node_decl
                | "on" IDENT block
A property line ends at a newline or ;. Legacy files that end every property with ; therefore parse unchanged.
5. Type system
5.1 Types
void does not exist as a name. A function with no -> clause returns nothing and cannot be used as a value.
5.2 Inference and annotation rules
Required annotations: every parameter type; every return type when the function returns a value; every field; every record member; every state that is not initialised from a literal.
Inferred: local let and fixed from the initialiser. let xs <- [1, 2, 3] is list of whole. let xs <- [] is ANI-T016 unless annotated.
Literal typing: whole literals are whole; they widen to real where a real is required (rule 5.3). Real literals are real.
Function return inference is not performed. A body that returns a value with no declared type is ANI-T005.
Lambda parameters may omit types only when the lambda is passed where a function type is expected (list.map(fn(x) { give x * 2 })); otherwise they are required.
5.3 Assignability and conversion
Conversions are never implicit between text and other types. "a" + 1 is allowed because + with a text operand is concatenation and converts the other side with to_text (rule 5.4); let s: text <- 1 is an error.
5.4 Operator typing
Real NaN compares unequal to everything including itself, as in IEEE.
5.5 Handling maybe T
x fallback y gives x if it has a value, else y.
x.has_value is a truth; x.value returns the payload or fails with ANI-R005.
Narrowing. Inside the block of when x is not none { ... } (and in the otherwise block of when x is none), a local immutable-in-the-block variable x has type T. A variable is narrowed only if it is a local let/fixed/parameter, is not captured by a lambda that assigns it, and is not assigned inside the block. Anything else is not narrowed and must use .value or fallback.
when x is none { give } at function level narrows x for the rest of the function when the block always leaves (give, fail, stop, skip).
5.6 Subtyping, traits and virtual dispatch
A class has at most one base class and any number of traits. class A is B, T1, T2 means B is the base (the first name must be a class if any is) and T1, T2 are traits.
A trait may extend other traits (trait X is Y). A trait method with a block is a default method and is inherited by every implementing class unless overridden.
A concrete class must implement every non-default trait method and every abstract method it inherits, with an identical signature (same parameter names are not required; types and count are). Mismatch is ANI-T013.
Overriding a base-class method requires the override keyword (ANI-T011 if missing, ANI-T012 if override has nothing to override). Overrides may not change the signature; return types are invariant.
Cyclic inheritance is ANI-T023.
5.7 Definite return and reachability
Every control-flow path of a function with a return type must end in give expr or fail ..., or be proven non-terminating (repeat while true with no stop). Otherwise ANI-T008. Statements after an unconditional give, fail, stop or skip are warning ANI-W002.
6. Semantics
6.1 Scopes and name resolution
Module scope holds define, record, class, trait, enum, fixed and top-level let, plus imports. All module-scope names are visible throughout the module regardless of order (forward references allowed). Module-scope let and fixed are initialised in source order when the module loads; reading one before its initialiser runs is ANI-R014 (compile-time detectable cases are ANI-T027).
Function scope holds parameters. Block scope holds locals introduced in { }. A local is visible from its declaration to the end of its block.
Shadowing. Declaring a name already declared in the same scope is ANI-T009. Shadowing an outer scope is allowed with warning ANI-W003.
Resolution order: local scopes, enclosing function scopes (for lambdas), module scope, from ... use names, module aliases, the always-loaded std.core names.
A name cannot be used as both a value and a module alias in one file.
6.2 Evaluation order
Left to right everywhere: operands, arguments, list and map literal elements, interpolation parts. and and or short-circuit. Argument evaluation completes before the call begins. Named arguments are evaluated in call-site order, not parameter order.
6.3 Value and reference semantics
whole, real, truth, enums and vector/matrix/quaternion/color types are values: assignment copies.
Records are values. let b <- a copies the record (shallow: a field that is a class, list, map or text refers to the same object). Implementations may share storage copy-on-write; the behaviour must be indistinguishable from copying.
Classes, lists, maps and closures are references. let b <- a makes b and a refer to the same object. Use .copy() on lists and maps for a shallow copy. Classes have no implicit copy.
Text is immutable; sharing is invisible.
Parameters are passed by value in the sense above (records copied, references shared). There are no by-reference parameters.
6.4 Assignment
target <- expr requires the target to be a declared mutable local, a parameter (allowed; parameters are mutable locals), a field accessed via self or a value, a list or map element, or a module-scope let. Assigning to a fixed is ANI-T019. Compound forms += -= *= /= %= are exactly x <- x op y with x evaluated once.
Assigning to a record field through an rvalue is an error: make_point().x <- 1 is ANI-T020. Assigning to a field of a record stored in a variable, field or list element is allowed and updates that stored record in place.
6.5 Control flow
when conditions must be truth (ANI-T006). There is no truthiness: when count { } is an error.
repeat n { } requires n: whole; zero or negative runs the body zero times. n is evaluated once.
repeat while c { } re-evaluates c before each iteration.
repeat each x in source { } iterates a list (in order), a map (iteration variables k, v; insertion order), a text (one text per code point), or a range. Mutating a list or map’s length during iteration over it is ANI-R009 (changing an element in place is allowed).
repeat i in a..b { } iterates whole values; the range is evaluated once; i is a fresh immutable binding per iteration.
stop leaves the innermost loop; skip jumps to its next iteration. Both are errors outside a loop (ANI-P010). They cannot cross a function or lambda boundary.
give outside a function or lambda is ANI-P009. In start and test blocks, give is not allowed; use exit(code).
6.6 Strings
text.length() counts Unicode code points. Indexing and slicing are by code point and are O(n); programs that need random access to large text should use list of text or the host. to_text formats: whole as decimal; real with the shortest representation that round-trips (1.5, 0.1, 1e+21; whole-valued reals print without a trailing .0 only in interpolation of wholes, so to_text(2.0) is 2.0); truth as true/false; none as none; lists as [1, 2, 3]; maps as [a: 1, b: 2]; records and classes by calling describe() if defined, otherwise TypeName { field: value, ... } (classes print TypeName@id).
6.7 Numeric behaviour
Integer overflow is a checked error (ANI-R002), not wrap-around. math.wrap_add, math.wrap_mul exist for hash code. Real arithmetic follows IEEE-754 float64; the VM must not use fused multiply-add or x87 extended precision, so results are identical across machines (determinism requirement N1, section 19.3). whole to real widening is exact below 2^53.
6.8 Closures
A lambda captures variables by reference to the variable’s storage. Captured locals are boxed at compile time (the checker marks every local that any lambda captures and assigns; read-only captures of effectively-final locals may be captured by value as an optimisation). A fresh loop variable per iteration means repeat i in 0..3 { fns.add(fn() -> whole { give i }) } produces closures returning 0, 1, 2. Captured variables live as long as any closure referencing them.
6.9 Error semantics
fail expr raises an error whose message is to_text(expr); fail some_error re-raises an existing error object. Control leaves the current function, running always blocks and releasing locals (refcount decrements, finish blocks) on the way, until an enclosing attempt with a matching rescue is found. rescue e { } matches any error; rescue e: IoError { } matches that class and subclasses; clauses are tried in order. An unmatched error continues to unwind. An uncaught error reaches the host runner, prints the diagnostic and stack trace, and exits with code 1. always blocks run on normal exit, give, stop, skip and error unwind. A fail inside always replaces the in-flight error and records the earlier one in error.cause.
7. Declarations in detail
7.1 Functions
define damage_after_armor(raw: whole, armor: whole <- 0, floor: whole <- 1) -> whole {
    give math.max(floor, raw - armor)
}
Defaults are evaluated at each call, left to right, and may refer to earlier parameters. Parameters with defaults must follow those without.
Named arguments: damage_after_armor(50, floor: 5). Positional arguments must come first. Unknown name ANI-T025; duplicate or already-supplied name ANI-T026.
No overloading and no variadics for user functions. Native functions may have overload sets (section 14.5).
Recursion depth limit 256 frames by default (--max-depth); exceeding is ANI-R006 with a trace of the first and last 8 frames.
Functions are first-class: let f <- area gives a fn(real, real) -> real. Methods bind as obj.method into closures (the receiver is captured).
define inside a function body is not allowed; use a lambda.
7.2 Records
record Spawn {
    pos: vec3
    kind: text <- "grunt"
    delay: real <- 0.0

    define distance_to(other: vec3) -> real { give (pos - other).length() }
}
let a <- Spawn(vec3(1, 0, 0))               # positional, then defaults
let b <- a with { kind: "boss", delay: 2.5 } # copy with changes
The constructor is generated: parameters are the members in order, those with defaults optional, usable with named arguments.
Records have structural equality and no identity. They may contain methods but no make, no inheritance, no traits in 0.3.
Records may not contain themselves directly (ANI-T028); through a list of or maybe they may.
7.3 Classes
abstract class Entity {
    field name: text
    field alive: truth <- true
    private field hp: whole <- 100
    shared field count: whole <- 0              # one per class, not per instance

    make(name: text) {
        self.name <- name
        Entity.count += 1
    }
    finish { Entity.count -= 1 }                # runs when the last reference is released

    abstract define update(dt: real)
    define hurt(amount: whole) {
        hp <- math.max(0, hp - amount)
        when hp == 0 { alive <- false }
    }
    shared define live_count() -> whole { give count }
}

class Orc is Entity, Damageable {
    field rage: real <- 0.0
    make(name: text) { super.make(name) }
    override define update(dt: real) { rage += dt }
}
Fields are read and written unqualified inside methods when no local or parameter shadows them; self.field always works. private limits access to the declaring class (not subclasses); there is no protected in 0.3.
make is the constructor; a class has at most one. A derived class’s make must call super.make(...) as its first statement if the base has a make with parameters or any field without a default; otherwise the call is implicit. Fields with defaults are initialised before make runs, in declaration order, base class first. A class with no make gets a generated constructor taking all fields without defaults, in order.
Using self as a value inside make before all non-default fields are assigned is ANI-T029 (prevents observing a half-built object).
finish runs deterministically when the reference count reaches zero, on the thread that released it. It must not store self anywhere (no resurrection; the runtime checks and reports ANI-R015) and any error inside it is logged and swallowed. Order: derived finish, then base finish.
shared members belong to the class: Entity.count, Entity.live_count(). A shared define has no self.
abstract: an abstract class cannot be constructed (ANI-T030); abstract methods have no body.
Instance creation: Orc("Grakk") (the class name is called). There is no new.
Type tests and casts: e is Orc, e as Orc (returns maybe Orc).
Equality is identity. A class may define define equals(other: Entity) -> truth and define describe() -> text; == does not call equals (use it explicitly), but to_text calls describe.
Inheritance depth has no hard limit; the style guide advises at most 3 levels. Composition (entity holds components) is the intended pattern for engine code.
7.4 Traits
trait Damageable {
    define hurt(amount: whole)
    define is_dead() -> truth { give false }       # default method
}
Traits have no fields and no constructors. A class may implement many. Trait-typed values (let d: Damageable <- orc) support only the trait’s methods. A trait method call is dispatched through a per-class interface table (section 10.5).
7.5 Enums
enum Mood { calm, alert, hunting }                 # values 0, 1, 2
enum Layer: whole { background <- 10, world <- 20, hud <- 30 }
Cases are accessed as Mood.calm. Each enum has .name (text), .value (whole), Mood.all() (list of Mood) and Mood.from_name(text) -> maybe Mood. Enums compare by case; they can be map keys. Enums have no payloads in 0.3; payload cases need match ([Reserved]).
7.6 Extension blocks [Stretch]
extend Creature { define wave() { ... } } adds methods to a class or record from outside its declaration. Extensions cannot add fields, cannot override, and are visible only where the extending module is imported. A name clash with an existing member is ANI-T009.
7.7 Weak references
field owner: weak Entity. Reading a weak value requires .get() which returns maybe Entity; it is none after the target has been destroyed. Assigning a strong reference into a weak field creates a weak reference automatically. weak is allowed on fields, locals and parameters of class type, and in list of weak C / map of K to weak C.
7.8 Tests
test "hurt clamps at zero" {
    let o <- Orc("Grakk")
    o.hurt(1000)
    expect(not o.alive)
}
test blocks are ignored by anima run and executed by anima test. Each runs in a fresh heap and module state. A failing expect fails the test and continues with the next test.
8. Modules, projects and capabilities
8.1 Modules
One .ani file is one module. Its name is its path relative to the project root with / replaced by . and the extension removed (world/creatures.ani is world.creatures). std.* and engine.* are built in (native) and shadow files of the same name (ANI-M006 warns when a project file has a reserved prefix).
8.2 Import forms
use std.math                    # access as math.sqrt(2)
use std.math as m               # m.sqrt(2)
use world.creatures             # access as creatures.Orc("x")
use "world/creatures.ani" as c  # explicit relative path from this file
from std.math use sqrt, clamp   # bare names sqrt, clamp
Without as, the alias is the last segment. Alias clash is ANI-T009. A from import may name functions, types and constants. Using an imported name that the module does not export is ANI-M003.
8.3 Resolution algorithm
std.* and engine.* resolve to registered native modules (error ANI-M005 if the name is unknown).
A dotted name resolves against each directory in the project paths list, in order, then the importing file’s directory.
A string path resolves relative to the importing file.
If more than one candidate matches, the first wins and a warning ANI-M007 lists the others.
If none matches: ANI-M001 with the paths tried.
8.4 Loading and initialisation
The loader parses and checks each module once, in dependency order. Import cycles are an error (ANI-M002) with the cycle printed. Module bodies (module-scope let and fixed) are initialised once, dependencies first. start exists only in the entry module; start in an imported module is ANI-M008 (use test blocks for module self-checks).
8.5 Exports
export is allowed before define, record, class, trait, enum and fixed. A module with no export exports nothing (it may still be the entry module). Re-export: export from world.creatures use Orc [Stretch].
8.6 The project block
project "Arena" {
    version 0.1
    target native.windows
    entry "arena/main.ani"           # only meaningful in an anima.project file
    paths "src", "vendor"
    runtime direct                   # bytecode is the 0.3 default; `direct` selects the reference evaluator
    capability time.clock
    capability cpu.parallel
    capability gpu.compute
}
project blocks live at the top of the entry module. A separate manifest file anima.project containing only a project block (header ANIMA 0.3) is also accepted, so a folder of modules can run with anima run ..
8.7 Capabilities
A capability grants a module access to a class of native functionality. Native modules declare which capability each function requires; calling a function whose capability is not declared in the entry project block is a compile-time error (ANI-M004) when statically visible, otherwise runtime ANI-R011.
Always available with no capability: std.core, std.math, std.json, std.random, std.log, std.test, std.host, and time.Clock (a pure fixed-step accumulator). File capabilities are further restricted to the project root (section 24).
9. Memory and runtime model
9.1 Value representation
A Value is 16 bytes: an 8-byte payload and a tag (type id, flags). Inline payloads: whole, real, truth, enum, none, and small vectors. Heap payloads are pointers to objects with a common header.
struct ObjHeader { uint32 refcount; uint16 type_id; uint8 flags; uint8 gc_color_unused; uint32 weak_slot; }
flags includes FROZEN (immutable text), HAS_WEAK (a weak-table entry exists), FINISHING. The header is 16 bytes. Objects are allocated with a size-class pool allocator; large objects use the system allocator. The allocator interface is abstract so an arena allocator can be added for engine data in 0.4.
9.2 Reference counting
Assignment and parameter passing increment; scope exit, overwrite and container removal decrement. When the count reaches zero: run the class finish (if any), release fields in reverse declaration order, then free. Release of long chains (a linked list of a million nodes) must not overflow the C++ stack: releases are queued in an explicit worklist and drained iteratively.
Cycles leak unless broken with weak. The runtime provides --leak-check: at exit it walks the live-object registry and prints every object still alive with its allocation site (function and line), exiting with code 5 if any exist. Debug builds always track allocation sites; release builds track them only under --leak-check.
9.3 Weak references
Weak handles index a global table of { object*, generation }. weak_slot in the header records the entry. When an object dies its entry is cleared and its generation bumped, so a stale handle reads as none. Cost: one table lookup per .get().
9.4 Containers
text: immutable; stored as length-prefixed UTF-8 with a cached code-point count (computed lazily); literals are interned per module.
list of T: contiguous. For whole, real, truth, vec2, vec3, vec4, color the storage is a packed array of the native type (no per-element tag), so a list of vec3 is directly uploadable to a GPU buffer. Other element types use a Value array. Growth factor 1.5x.
map: open-addressing hash table plus a dense insertion-order array; iteration is in insertion order, removal marks a tombstone and compacts on resize. Hashing uses a fixed seeded function (never addresses), so iteration and hashing are deterministic across runs and machines.
Records are boxed objects with a header and a flat field array; copying allocates.
Closures hold a function prototype pointer and an array of captured-variable cells.
9.5 Threads
The VM and heap are single-threaded: only one thread executes ANIMA code at a time. Native functions may use threads internally (for example parallel_sum) but must not touch ANIMA objects from them. parallel_for with an ANIMA body is [Stretch] and runs each iteration on a separate VM instance with no shared heap, accepting only a fn whose captured variables are all immutable values (checked at compile time); results are collected back on the main thread.
9.6 Limits
--deterministic additionally freezes time.now, seeds default randomness to 0, disables log timestamps, and makes any host call tagged non-deterministic an error (ANI-R017).
10. Bytecode and virtual machine
10.1 Design
A stack-based VM with typed instructions. Because the checker proves types, the compiler emits ADD_W (whole) or ADD_R (real) rather than a generic add, so the interpreter loop does no tag dispatch for arithmetic. Each function compiles to a chunk: code bytes, a constant pool, a line table (instruction offset to line and column), an exception-handler table, and metadata (parameter count, local slot count, upvalue descriptors). Instructions are one opcode byte followed by 0 to 3 operands of 1, 2 or 4 bytes (little-endian). The interpreter is a switch loop; computed-goto dispatch is allowed under GCC/Clang only behind a macro, and the MSVC build must use the plain switch.
A call frame holds the chunk pointer, instruction pointer, base slot index in the shared value stack, and the closure. The value stack grows to the depth limit times the maximum slots per function and is allocated once. Module-scope variables live in a per-module global array indexed by slot.
10.2 Instruction set
Roughly 85 opcodes. The exact encoding is frozen when milestone C2 completes; anima dis prints it, and the disassembly of every conformance test is stored as a golden file so accidental code-generation changes are caught in review.
10.3 Calling convention
The caller pushes the callee value then arguments left to right; CALL n creates a frame whose locals begin at the first argument. Default arguments and named arguments are resolved at compile time into the positional order (defaults become inline code at the call site). A method call passes the receiver as local 0. RET/RET_V pop the frame, release locals in reverse order, and push the result.
10.4 Exceptions
The handler table maps instruction ranges to a handler offset and the scope depth to unwind to. THROW looks up the innermost handler covering the current instruction; if none exists in the frame, it unwinds frames (running always blocks, which the compiler emits as inline handlers marked ALWAYS). Stack traces are built from the frame chain and line tables at the moment of the throw and attached to the error object.
10.5 Method dispatch
Class methods: each class has a vtable (array of function pointers). CALL_M slot indexes it with the receiver’s class. A derived class copies the base table and replaces overridden slots.
Trait methods: each class has an interface table, a small sorted array of { trait_id, method_slots[] }. CALL_I id finds the trait entry by binary search on the receiver’s class. A one-entry inline cache keyed on class pointer is added in C8.
Shared (static) functions are resolved at compile time to a direct call.
10.6 Bytecode cache [Stretch]
anima compile file.ani -o file.anic writes a versioned binary of all chunks. The format has a magic number, a bytecode version, a hash of the source and imported module hashes. It exists for load-time speed and is never an ABI promise.
11. Compiler pipeline
source text
  -> Lexer         tokens with spans
  -> Parser        AST (arena allocated, immutable after parse)
  -> Checker       symbol tables, types, narrowing, lint warnings -> annotated AST
  -> Compiler      bytecode chunks, constant pool, line tables
  -> VM            execution
11.1 Lexer
Pull-based, one token lookahead plus checkpoint. API sketch:
class Lexer {
public:
    Lexer(const SourceFile& file, Diagnostics& diag);
    const Token& peek();
    Token next();
    Checkpoint mark();
    void rewind(Checkpoint);
};
11.2 Parser
Recursive descent for items and statements; precedence climbing for expressions using the table in section 4.4. Error recovery: on a syntax error the parser records a diagnostic and synchronises by skipping to the next newline-terminated statement start or a closing } at the current depth, then continues, so one run reports many errors (maximum 20 per file, then “too many errors”). Nodes produced during recovery are marked Invalid and ignored by later phases so that one mistake does not cascade.
AST node catalogue (all nodes carry a source span): Module, Project, Use, FromUse, Fixed, Function, Param, Record, Class, Field, Make, Finish, Trait, Enum, Extend, App, State, Scene, Node, OnEvent, Start, Test, Block, Let, Assign, CompoundAssign, When, RepeatCount, RepeatWhile, RepeatEach, RepeatRange, Give, Stop, Skip, Announce, Fail, Attempt, Rescue, ExprStmt, Literal(whole/real/text/truth/none), TextInterp, ListLit, MapLit, Range, Ident, Member, Index, Slice, Call, NamedArg, Lambda, Unary, Binary, Is, As, With, Fallback, Self, Super.
11.3 Checker passes
Declare: walk module items, create symbols for every module-level name (functions, types, constants), build the import graph and load dependencies.
Resolve types: resolve every annotation to a type; detect inheritance cycles, record layout cycles, duplicate names.
Check signatures: override and trait conformance, abstract completeness, default parameter ordering, make rules, capability references.
Check bodies: scopes, inference, assignability, operator typing, narrowing, definite return, loop/give context, closure capture analysis (marks boxed locals), constant folding of fixed.
Lint: unused variables, imports and parameters, unreachable code, shadowing, deprecated constructs, let that could be fixed.
Output is an annotated AST where every expression has a resolved type and every identifier a resolved symbol, plus a list of diagnostics. anima check stops here and never runs code.
11.4 Compiler
One pass over the annotated AST per function. Responsibilities: select typed opcodes; emit boxed-variable access for captured locals; lower repeat each to iterator opcodes; lower attempt/rescue/always to handler-table entries; inline default arguments and reorder named arguments; fold constant expressions and fixed values; emit line-table entries per statement and per call. The compiler must not fail on a checked AST; any failure is an internal error (ANI-I001) that prints the offending node’s span.
11.5 Source spans and snippets
A SourceMap owns file text and a line-start table so a byte offset converts to line and column in O(log n). Diagnostics print the source line plus carets under the span; a multi-line span prints its first line.
12. Diagnostics and error model
12.1 Format
error[ANI-T002]: type mismatch
  --> src/creatures.ani:14:26
   |
14 |     let hp: whole <- 1.5
   |                      ^^^ expected `whole`, found `real`
   = help: use to_whole(1.5) to truncate, or math.round(1.5)
Warnings use warning[ANI-W003]. --format json prints one JSON object per diagnostic (code, severity, file, line, column, end_line, end_column, message, help) for editors and CI. Help text is mandatory for every error with a likely fix; a near-miss name (edit distance up to 2) always yields “did you mean x?”.
12.2 Exit codes
0 success; 1 uncaught runtime error or failed test; 2 compile-time errors (lexical, parse, type, module); 3 command-line usage error; 4 internal error (a bug; print “please report” and the code); 5 leak check failed.

13.11 std.host and std.ui

13.12 Library design rules
Every function has a documented signature in the module’s .ani stub file (checked in, used for docs generation and for checker tests) and a registered native or ANIMA implementation; a test enforces that the two agree.
Functions that can fail raise a typed error subclass; functions that “may not find” return maybe.
No function mutates its arguments unless its name or the section above says so (sort, reverse, add and so on mutate; sorted copies [Reserved]).
Names are snake_case, short, and spelled out (length, not len).
No global mutable state in the library; randomness and clocks are objects.
14. C++ host API
The host API is the contract between the C++ engine and ANIMA. It is how every future engine feature (windowing, renderer, physics, audio, assets) becomes available to scripts, so it is the most important interface in 0.3 to get right. It is source-level stable within 0.3.x and is not an ABI promise.
14.1 Principles
Typed. Every native function, method and class declares ANIMA types. The checker uses them, so a wrong call from ANIMA is a compile error, not a crash.
Capability-gated. Every native function names the capability it requires (or none).
No raw access. ANIMA never receives pointers, OS handles or unbounded memory. Native objects are opaque, refcounted ANIMA objects with a finaliser.
Errors are values. A native function reports failure by throwing anima::NativeError (or a subclass mapped to a built-in error class); the VM converts it into a catchable ANIMA error. C++ exceptions never propagate through the VM loop.
Single-threaded contract. Native code is called on the VM thread and may not call back into the VM from another thread.
14.2 Core types
namespace anima {
  enum class Cap { None, CpuParallel, GpuCompute, GpuDxrQuery,
                   IoRead, IoWrite, IoEnv, TimeClock, UiScene };
  struct Type;                       // type descriptor, built with Type::whole(), Type::list(t), ...
  class  Value;                      // 16-byte tagged value
  class  Args;                       // typed accessor for a call's arguments
  class  Host;                       // owns modules, classes, capabilities
  class  ModuleBuilder;              // fluent registration
  class  ClassBuilder;               // fluent native-class registration
  using  NativeFn = std::function<Value(Args&)>;
}
Args exposes whole(i), real(i), truth(i), text(i) (a std::string_view valid for the call), list(i), obj<T>(i) for native class instances, fn(i) for callbacks, and has(i) for defaulted parameters.
14.3 Registering a module
anima::Host host;
host.module("std.math")
    .fn("sqrt").takes({Type::real()}).returns(Type::real()).cap(Cap::None)
        .impl([](Args& a) { return Value(std::sqrt(a.real(0))); })
    .fn("clamp").overload({Type::whole(), Type::whole(), Type::whole()}, Type::whole(), ClampWhole)
                .overload({Type::real(),  Type::real(),  Type::real()},  Type::real(),  ClampReal);
14.4 Registering a native class
host.module("engine.window")
    .cls("Window")
        .make({Type::text(), Type::whole(), Type::whole()}, [](Args& a) {
            return NativeObject::create<WindowImpl>(a.text(0), a.whole(1), a.whole(2));
        })
        .method("close").returns(Type::none()).impl([](Args& a) { a.self<WindowImpl>().close(); })
        .method("size").returns(Type::of("vec2")).impl([](Args& a) { /* ... */ })
        .field_ro("title", Type::text(), [](WindowImpl& w) { return Value(w.title()); })
        .finalizer([](WindowImpl& w) { w.destroy(); });
NativeObject instances participate in reference counting; the finaliser runs when the last ANIMA reference is released (same rules as finish, section 7.3). Native classes may declare is traits that ANIMA already defines, so engine objects can satisfy ANIMA interfaces.
14.5 Overloads and generics
Native functions may have overload sets resolved by the checker on argument types at compile time (exact match first, then with whole to real widening; ambiguity is ANI-T004). The built-in generic list and map methods (map, filter, reduce, sort_by) are typed by the checker through a small internal template mechanism that is not exposed to user code or to the host API in 0.3. Host modules that need generic behaviour use value.
14.6 Errors, capabilities and limits
throw NativeError("message") becomes NativeError; throw IoError(...), RangeError(...) and ParseError(...) map to their ANIMA classes.
The VM verifies at load time that every capability a referenced native needs is declared in the project block (section 8.7). The check also runs at call time for dynamic paths.
Host::set_limits({max_native_alloc_mb, max_text_bytes, ...}) bounds native allocations made on behalf of scripts.
14.7 Ownership and lifetimes
Values passed in are borrowed for the call; to keep one, call Value::retain() and store it (the host must release() it).
Returned objects are owned by the VM.
Callbacks: Args::fn(i) returns a Callable that can be stored and invoked later (callable.invoke({args})) on the VM thread. The host must release callables before shutdown; --leak-check reports leaked ones.
14.8 Porting the 0.2 built-ins
The calls remain reachable with their 0.2 dotted spelling when the matching module is imported without an alias (use std.cpu then cpu.logical_cores()), so migrated programs keep working.
14.9 Testing native modules
Every native module ships with a stub file (std/math.ani.stub) listing its ANIMA signatures. A unit test loads each stub and verifies that the registered native types match exactly; a conformance test per module exercises every function including every error path. Native modules must be tested under ASan and UBSan on the Linux build.
14.10 Stability rules
Adding functions is a minor change. Changing a signature, a capability or an error class is breaking and requires a spec revision and a deprecation period of one minor version.
15. Unified UI system
15.1 Model
UI in ANIMA is ordinary language, not a separate dialect. app, scene and node are declarations that build a typed scene tree in memory. In 0.3 that tree can be built, queried, driven by events, bound to state and dumped as text. Drawing it on screen natively is a later milestone (0.5). The browser JavaScript runtime continues to render legacy .anima files until it is retired; new features are not added to it.
15.2 Declarations
app Hud {
    state score: whole <- 0
    state title <- "Score"              # inferred as text

    define bump(n: whole) { score += n }

    scene Main {
        node Screen: Column {
            gap: 18
            fill: "#070912"
            node Label: Heading { text: "{title}: {score}"; scale: 40; motion: Reveal }
            node Hit: Button {
                text: "Hit"
                on click { bump(1) }
            }
        }
    }
    scene Settings { ... }
}
app may contain state, define (app-local functions), and one or more scene blocks; the first scene is the initial scene unless the entry module’s start navigates elsewhere.
node Name: Type { ... }: Name is unique within its scene (ANI-T009); Type is a node type from std.ui or a user class that extends ui.Node; omitting : Type uses the generic Box.
A property line is name: expression; the expression may reference state names, constants, and functions. A property whose expression reads state is bound (15.6).
Child node blocks nest. on event { ... } attaches a lambda body to an event on that node.
state is only legal inside app; assignments to state (score <- score + 1) schedule re-evaluation of bound properties at the end of the current event.
Programs may have both an app and a start. If both exist, start runs and may call ui.run(Hud); if only app exists, the runner builds the first scene and (in 0.3) dumps it or runs an event script (section 16.5).
15.3 Node types and property catalogue
The initial catalogue is taken from the legacy samples and docs and must be completed from the full legacy runtime in WP F1. Unknown legacy properties found there are added to the registry or reported to the owner before the migrator is declared complete.
Node types: Box (default), Column, Row (shorthand for Box with flow preset), Heading, Paragraph, Small, Button, Canvas. (canvas in legacy files is migrated to Canvas.)
Types: Length is real (pixels) or a CSS-length text; Spacing is real or a one-to-four-value text; Paint is Color or gradient text; Flow is column(...) / row(...) with named options (cross, route, gap, wrap); Align, Place, TextCase are enums. A table of exact accepted forms is generated from the registry (anima ui-catalog) and checked in as the source of truth.
15.4 Validated literals
For UI value types, a text literal is accepted where the type is Color, Length, Spacing, Paint, Flow, or an enum, and is parsed and validated at compile time. ink: "#75ddff" is valid; ink: "#75ddzz" is ANI-T031 with the location of the bad character. This keeps every legacy file valid without forcing a new literal syntax, and turns typos that the browser runtime ignored silently into errors. Non-literal text is not implicitly converted; use color.hex(...).
15.5 Events and actions
Events: click, press, hover, focus (from the legacy set; the registry may add more). Handler bodies are lambdas with access to app state and functions. Built-in UI functions from std.ui:
Browser-only GPU bridge calls in legacy files (gpu.setRayTracing, gpu.roomRaytrace, gpu.resetRayTracing, gpu.stop) are not in std.gpu. The migrator converts them to calls of legacy.browser_call("name", args) which type-checks but raises ANI-R011 outside the browser runtime, and prints a migration note. They are removed when native equivalents exist.
15.6 State and binding
Property expressions are compiled into binding functions that list the state names they read. Assigning a state variable marks dependent bindings dirty; at the end of the event handler the runtime re-evaluates dirty bindings in tree order and records changed properties (a changeset). Rules: binding functions must be pure (no calls to functions with side effects; the checker enforces this by allowing only pure built-ins, pure user functions marked by inference, and state reads); a binding that reads state it also writes is ANI-T032; evaluation cycles are impossible by that rule. The first rendering backend (0.5) consumes changesets; in 0.3 they are asserted in tests.
15.7 Scene dump format
app Hud
  state score = 0
  scene Main (initial)
    Column Screen { gap: 18, fill: #070912 }

snake_case functions and variables, PascalCase types, kConstant, trailing underscore for private members; one class per header where practical.

19. Performance and determinism
19.1 Benchmarks and targets
Baselines for new rows are recorded in C8 on the Windows and Linux reference machines; a benchmark regression of more than 5 percent fails the gate.
19.2 Optimisation backlog (after correctness)
Superinstructions for common pairs (LOAD_L+LOAD_L+ADD_W); inline caches for CALL_M and CALL_I; integer loop specialisation for repeat i in a..b; avoiding record copies through copy-on-write; text interning of repeated constants; computed goto on GCC/Clang. Each optimisation needs a benchmark that demonstrates it.
19.3 Determinism requirements
N1 Real arithmetic identical across machines (no FMA contraction: compile with /fp:precise and -ffp-contract=off). N2 Map iteration is insertion order. N3 Hashing never depends on addresses. N4 Random sequences defined by the PCG specification. N5 to_text of reals uses a specified shortest round-trip algorithm (Ryu or Grisu in-tree). N6 Sorting is stable. N7 No behaviour depends on locale; the C++ runtime runs in the “C” locale.
20. Migration and compatibility
20.1 Breaking changes from 0.2 to 0.3
20.2 Rewriting .ani 0.2 files
The migrator parses with the 0.2 grammar and rewrites with these rules: (1) Replace the header. (2) Track names declared by let in file order; a later let of an already-declared name becomes an assignment x <- .... (3) A name first assigned inside a define and read in start (or another define) is hoisted to a module-scope let with a default of 0, "", false or [] chosen from its annotation or first value, and a migration note. (4) perform x becomes x(). (5) series annotations become list of real. (6) Add capability lines to the project block for each native module used. The output is checked with the 0.3 checker before it is written; if checking fails the report lists the remaining errors and the original is untouched.
20.3 Rewriting .anima (legacy UI) files
The migrator also emits a migration report (file.migration.md) listing every rewrite, every note, and every unknown property or node type.
20.4 Compatibility mode
--compat 0.2 runs a 0.2 file through the reference evaluator unchanged (including its semantics: double whole, global scope, no static checking). It exists for one release as a safety net and prints a deprecation banner. It is removed in 0.4.
20.5 Deprecation policy
A feature is deprecated for one minor version with a warning code and a documented replacement, then removed. Reserved words and the grammar are frozen after milestone B except by a written decision (section 26.1).

23. The path to a game engine
23.1 Division of labour
The C++ engine core owns renderer, physics, audio, input, windowing, asset loading, entity storage and memory arenas. ANIMA owns gameplay logic, tools, UI, content definitions and configuration, scene scripting, and automation. This is the Lua/C# model and is the realistic route for a two-person studio. Writing the whole engine in ANIMA would require an AOT compiler, raw memory and pointer types, and a much larger safety story; it is not a goal.
23.2 What 0.3 puts in place
23.3 Roadmap after 0.3
23.4 Hot reload design note
Because modules are compiled to bytecode and objects carry class ids, reloading a module can replace function bodies in place. The rule for 0.4: functions reload, data does not (existing objects keep their old layout; fields added or removed require a restart, reported explicitly). The 0.3 requirement is only that the loader keeps module state in a replaceable table and never caches code pointers across calls.
23.5 Reserved hooks
Keywords reserved now (3.3): async await case generic handle kernel match shader task unsafe where yield native switch. Reserved syntax: ?, match, non-ASCII identifiers, export from. Reserved library prefixes: engine.*, gpu.*.
24. Security and sandboxing
ANIMA programs are treated as untrusted by default, because scripts will be shared and loaded by tools.
Capabilities (8.7) gate every host feature; there is no eval, no dynamic loading of native code, and no reflection that can reach the host.
Filesystem: io.* paths resolve under the project root; absolute paths, drive letters, UNC paths and any .. that leaves the root are rejected with IoError. Symbolic links that point outside are rejected. An explicit capability io.any is not provided in 0.3.
Resource limits (9.6) make runaway scripts stoppable; hosts embedding ANIMA should set them.
Memory safety: no raw pointers in the language; all indexing is bounds-checked; integer overflow is checked; the VM validates bytecode loaded from the cache (stretch) before running it.
Native modules are registered in C++ by the embedding host only; scripts cannot register them.
Supply chain: no third-party code in 0.3; the build is reproducible from a clean clone.
Fuzzing (18.1) covers all untrusted-input surfaces: lexer, parser, checker, JSON parser, migrator.

26. Governance and open items
26.1 Change control
After B10, any change to grammar, reserved words, type rules or the host API requires: (1) a written note in the decision log with the reason and alternatives; (2) a spec revision; (3) updated tests in the same change; (4) sign-off by the language owner and one reviewer. 26.2 Decision log
26.3 Open questions to resolve before the 0.3b freeze
Spelling: are make (constructor), finish (destructor), give (return), fallback (maybe default) and weak the final words? They are readable and unused by other languages’ common keywords, but they are taste calls.
Whole division: / between wholes truncates (matches C++, C# and Java). The alternative is always-real division plus a separate integer operator. This spec chooses truncation; confirm.
Legacy source of truth: WP F1 needs the full legacy JS runtime (the browser Anima.parse/mount implementation) and the docs app’s structural checker. Only the shipped samples and docs were available when this spec was written. Confirm where the complete runtime source lives.
Editor support: is a TextMate/VS Code grammar for .ani wanted in 0.3 (listed as stretch)?
Platforms: Windows is the primary target and the primary release platform; Linux is a CI and tooling platform. Is macOS in scope for the CLI? (Assumed no.)
Naming of the UI Box: keep the legacy “node with no type” as Box, or keep it untyped?
Style guide: adopt the conventions in 3.3 and 17.3 as the official style guide (assumed yes).

A.2 Fixed-step simulation with components
ANIMA 0.3
project "Arena" {
    target native.windows
}
use std.random
use std.time

trait Component {
    define update(dt: real)
}

class Body {
    field pos: vec3 <- vec3(0, 0, 0)
    field vel: vec3 <- vec3(0, 0, 0)
}

class Mover is Component {
    field body: Body
    define update(dt: real) {
        body.pos <- body.pos + body.vel * dt
    }
}

class Entity {
    field name: text
    field parts: list of Component <- []
    define add(part: Component) { parts.add(part) }
    define update(dt: real) {
        repeat each p in parts { p.update(dt) }
    }
}

start {
    let clock <- time.Clock(1.0 / 60.0)
    let rng <- random.Random(42)
    let body <- Body()
    body.vel <- vec3(rng.next_real(), 0, 0)
    let hero <- Entity("hero")
    hero.add(Mover(body))

    repeat 120 {
        let steps <- clock.advance(0.016)
        repeat steps { hero.update(clock.step) }
    }
    announce "x after about 2 s: {body.pos.x}"
}
